## 1. Executive Summary

Milestone 3 implements both web interfaces for Signal Passport as two strictly separated, independently runnable applications:
1. **App One: Generator (`apps/passport`)** — Runs on port 3000. Provides wallet input validation (using M1's EIP-55 validator), a fixed 30-day observation window (`2026-08-13` to `2026-09-12`), progressive multi-state loading feedback (NDJSON streaming: fetching -> normalizing -> calculating), metric display using canonical `METRIC_LABELS`, evidence drill-down linking to live Blockscout transaction URLs, and single-click JSON export.
2. **App Two: Independent Consumer (`apps/consumer`)** — Runs on port 3001. Provides offline bundle import (drag-and-drop or file picker) and executes four sequential validation steps: (1) schema version and structure, (2) subject address format, (3) evidence reference resolution (dangling reference detection), and (4) SHA-256 integrity verification. Displays separate cards for Integrity and Publication status per PRD §8/§9.

Crucially, **The Non-Negotiable Structural Rule (PRD §9)** has been strictly enforced and proven:
- App Two is an independent process on port 3001 with its own `package.json`.
- App Two has **ZERO dependency on `packages/analysis`** and zero calls to Blockscout.
- The Cross-App Proof demonstrates App Two importing, validating, and detecting tampering on a real bundle **while App One is completely stopped and dead (`ECONNREFUSED` on port 3000)**.

## 3. App One: Generator Pipeline & Evidence Drill-Down

- **Subject Address Input**: Uses M1's `validateEthereumAddress` to enforce checksum and hex format. Displays sample wallet `0xc82f8B79Cd34bD98b1abEC72475F2a73Eb15CFA8` and the fixed 30-day observation window (`2026-08-13` to `2026-09-12`).
- **Progressive Loading**: NDJSON streaming route (`/api/analyze`) streams real pipeline phases:
  - Phase 1: `fetching` — querying Blockscout REST v2 API with cursor pagination
  - Phase 2: `normalizing` — converting raw items to `NormalizedTransaction`s, filtering to 30-day window, deduplicating
  - Phase 3: `calculating` — computing 3 claims, generating evidence records, packaging into `createPassportBundle`
  - Phase 4: `complete` — returning complete verified bundle
- **Evidence Drill-Down**: Each metric card displays its canonical label from `METRIC_LABELS` and can be expanded to show backing transactions with timestamps, sender/recipient, and live links to Blockscout explorer (`https://eth.blockscout.com/tx/0x...`).
