## 1. Executive Summary

1. **`packages/verification/src/canonical.ts`**: Implements recursive key sorting, array order preservation, decimal string representation for large integers/BigInt, and strict rejection (throwing `TypeError`) for non-finite values (`NaN`, `Infinity`, `-Infinity`) and ambiguous `-0`.
2. **`packages/schema/src/bundle.ts`**: Defines runtime-validated Zod schemas for `PassportBundle`, `PassportPayload`, `IntegrityRecord`, and optional `PublicationRecord`.
3. **Empty claims design verification**: Confirmed that `payload.claims` uses `z.array(claimSchema)`, which structurally permits an empty array (`claims: []`) for zero-qualifying-activity queries per PRD §9, without modifying M1's `claimSchema` (which retains `.min(1)` for individual claims).
4. **`packages/verification/src/digest.ts`**: Computes SHA-256 digests over `payload` only (excluding envelope fields `integrity`, `schema_version`, and `publication`). Provides `verifyBundleIntegrity` and `createPassportBundle`.
5. **Cross-process determinism**: Proven via a genuinely spawned Node child process executing `tests/helpers/cross-process-worker.ts`, verifying byte-identical canonical JSON and digest across process boundaries.
6. **Real bundle artifact**: Pipeline executed against `fixtures/real/` (100 raw items, 28 qualifying transactions), generating and persisting `fixtures/real/passport-bundle.json`. Download/reload fidelity verified with zero field loss and unchanged digest.

## 3. Detailed Technical Verification

### 3.1 Task 0 — Write-Path Integrity and Prose Restoration
- **Root Cause Identified**: In PowerShell environments, piping strings or passing non-ASCII content through default console codepages converts characters outside Windows-1252/ASCII (such as section symbols `§` and em-dashes `—`) into literal `0x3F` (`?`) substitution bytes.
- **Remediation**:
  - Restored all occurrences in `docs/METHODOLOGY.md` and `docs/verification/M1.md`.
  - Established strict write-path policy using `write_to_file` and Node `fs.writeFileSync` with explicit UTF-8 encoding.
  - Executed throwaway round-trip verification:
    - Input: `Section §7 — backtick \`no\` test`
    - Hex bytes: `53656374696f6e20c2a73720e28094206261636b7469636b20606e6f602074657374`
    - BOM: `false`, Control bytes: `false`, String match: `true`.
  - Task 0 committed in isolation as `8bac687`.

### 3.2 Task 1 — Canonical JSON Serialization (`packages/verification/src/canonical.ts`)
- **Key Sorting**: Uses lexicographical UTF-16 code unit ordering (`Object.keys().sort()`), applied recursively to all nested objects.
- **Array Order Preservation**: Array elements are serialized in their exact source order. Elements are not sorted. Object elements inside arrays have their keys recursively sorted.
- **Large Integer Representation**: `BigInt` values are serialized as decimal strings per PRD §8. Integers outside JavaScript's safe integer range (`Number.MAX_SAFE_INTEGER`) passed as numbers throw `TypeError` to avoid precision truncation.
- **Non-Finite Number Policy**: Throws `TypeError` for `NaN`, `Infinity`, `-Infinity`, and ambiguous `-0`.
- **Whitespace**: Compact representation with zero whitespace between tokens.

### 3.3 Task 2 — Bundle Envelope & Empty Claims Schema (`packages/schema/src/bundle.ts`)
- Minimum envelope structure per PRD §8:
  - `schema_version`: string (e.g. `"1.0.0"`).
  - `payload`: `passportId`, `subjectAddress`, `sourceChainId`, `snapshotVersion`, `generationTimestamp`, `observationWindow`, `coverage`, `claims`, `evidence`, `methodologyVersion`.
  - `integrity`: `algorithm` (`"sha256"`), `digest` (64-char hex string).
  - `publication`: optional/undefined in P0.
- **Empty Claims Analysis**: M1's `claimSchema.evidenceIds` has `.min(1)`. In `passportPayloadSchema`, `claims` is defined as `z.array(claimSchema)`. An empty array `[]` is completely valid under `z.array()`. When zero qualifying activity occurs in M4, the generator will emit `claims: []`, meaning individual claims without evidence are never created. **Zero changes were required to M1 schemas.**

### 3.4 Task 3 — SHA-256 Digest & Verification (`packages/verification/src/digest.ts`)
- **Payload-Only Scope**: The SHA-256 hash is computed exclusively over `canonicalJsonBuffer(payload)`. Modifying `schema_version`, `integrity`, or `publication` does not alter the digest.
- **Cross-Process Mechanism**:
  1. Main test process canonicalizes `samplePayload` and computes SHA-256 digest in memory.
  2. Main test process spawns a fresh Node child process running `tests/helpers/cross-process-worker.ts` via `spawnSync(process.execPath, [tsxBin, workerPath], { input: JSON.stringify(samplePayload) })`.
  3. Worker independently parses JSON, runs `canonicalJsonStringify`, computes `computePayloadDigest`, and prints `{ canonical, digest }`.
  4. Test asserts exit code 0, empty stderr, and identical canonical JSON string and digest between processes.
- **Tamper Detection**: Mutating any payload field (e.g. claim value from 28 to 999) causes `verifyBundleIntegrity` to return `isValid: false`.
- **Tamper-and-Rehash Semantics**: Mutating payload and recomputing `integrity.digest` to match passes `verifyBundleIntegrity`. The test asserts this behavior and includes documentation explaining PRD §8's rule: a bundled digest detects accidental modification, not authenticity.

### 3.5 Task 4 — Real Fixture Bundle Generation (`fixtures/real/passport-bundle.json`)
- Ingested real fixture data: `fixtures/real/page-1.json` (50 items) + `page-2.json` (50 items) + `metadata.json`.
- Executed M1 normalization and metrics:

  - 12 active days

  - BOM: `false`, Control bytes: `false`
