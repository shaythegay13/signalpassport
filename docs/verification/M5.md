## 3. The 5 Hard Grounding Rules & Enforcement Pipeline

All model outputs must pass through `validateAiExplanation` in `packages/analysis/src/ai/validation.ts` in strict sequential order before being accepted:

1. **Schema Conformance (Step 1)**:
   - Validated against `aiExplanationSchema` via Zod.
   - Requires `summary` (non-empty string <= 1000 characters) and `evidenceIds` (array of strings).
2. **Evidence Reference Resolution (Step 2)**:
   - Every cited ID in `evidenceIds` must be a member of `payload.evidence`.
   - If any evidence ID does not exist in the payload, the explanation is rejected (`"Cited evidenceId '...' is not present in payload.evidence"`).
3. **No Invented Numbers (Step 3)**:
   - Regex extraction finds all numeric tokens in the summary text (e.g. counts, amounts, percentages).
   - Only numbers matching exact claim values (e.g. `28`, `12`, `10`), chain ID (`1`), observation window dates (`2026`, `08`, `13`, `09`, `12`), or evidence counts are permitted.
   - If an unverified number appears (e.g. `"$5000 volume"`), the explanation is immediately rejected.
4. **Coverage Integrity (Step 4)**:
   - If `payload.coverage.coverageStatus` is `"partial"` or `"unknown"`, the summary is prohibited from claiming completeness.
   - Banned phrases when partial: `"complete"`, `"exhaustive"`, `"full history"`, `"entirety"`, `"comprehensive"`, `"all transactions"`.
5. **No Identity, Ownership, or Causal Speculation (Step 5)**:
   - Banned ownership phrases: `"belong(s)? to"`, `"owned by"`, `"wallet holder is"`, `"identity is"`, `"is an entity"`.
   - Banned causal phrases: `"because"`, `"due to"`, `"in order to"`, `"caused by"`, `"as a result of"`, `"since the user"`.

## 4. Validation-Failure & Resilience Policy

The system implements a **fail-closed, highly resilient architecture**:
- **Why fail closed?** In a fintech verification tool, an ungrounded or hallucinated summary completely undermines trust. Displaying false numbers or hallucinated evidence references is worse than displaying a deterministic summary or no explanation.
- **1 Repair Feedback Attempt**: If validation fails on attempt 1, the pipeline reconstructs the prompt, appending:
  ```
  PREVIOUS ATTEMPT REJECTED: <exact validation error>
  CORRECT THIS SPECIFIC DEFECT. Return only valid JSON conforming strictly to the rules.
  ```
- **Deterministic Fallback**: If attempt 2 also fails, or if the model network call times out, encounters HTTP 5xx, or fails due to missing API keys, `generateExplanation` automatically calls `generateDeterministicExplanation(payload)`.
- **Deterministic Summary Format**:
  `"Observed 28 successful outgoing transactions across 12 active UTC days to 10 unique recipient addresses on Ethereum Mainnet during the declared 30-day UTC window (2026-08-13 to 2026-09-12). Coverage is complete for the declared query scope."`
  - Marked with `model: "deterministic-fallback"` and `isFallback: true`.
- **Non-blocking Invariant**: Model failures, timeouts, and JSON errors are caught. The API route (`/api/explain`) returns HTTP 200 with the fallback explanation. Generating and exporting the passport bundle never blocks.

## 5. Byte-Identical Digest Preservation (AC 5)

Per PRD §8 & §10, AI explanations are display metadata attached to the bundle envelope, NOT part of the canonical payload.

### Schema Diff
In `packages/schema/src/bundle.ts`:
```diff
 export const passportBundleSchema = z.object({
   schema_version: z.string().min(1),
   payload: passportPayloadSchema,
   integrity: integrityRecordSchema,
-  publication: publicationRecordSchema
+  publication: publicationRecordSchema,
+  explanation: aiExplanationSchema.optional()
 });
```

- `passportPayloadSchema` remains completely untouched.
- `computePayloadDigest(bundle.payload)` computes the SHA-256 digest over the canonical JSON serialization of `payload` only.
- In `tests/m5-ai-explanation.test.ts`, AC 5 verifies:
  ```typescript
  const digestWithout = computePayloadDigest(payload);
  const bundleWithExplanation = { ...bundle, explanation };
  const digestWith = computePayloadDigest(bundleWithExplanation.payload);
  assert.strictEqual(digestWithout, digestWith);
  assert.strictEqual(verifyBundleIntegrity(bundleWithExplanation).isValid, true);
  ```

## 6. App One & App Two Integration

### App One: Generator (`apps/passport`)
- Includes an **AI Qualitative Synthesis** card below the deterministic claims.
- Dispatches `POST /api/explain` asynchronously after bundle generation.
- Displays:
  - Model badge (`openai/gpt-oss-120b` or `deterministic-fallback`).
  - Verification badge (`Grounded & Verified` vs `Deterministic Fallback`).
  - Verbatim summary and grounded evidence pills.
  - Disclaimer: *"This explanation is qualitative display text on the envelope. It does not alter or participate in the SHA-256 payload digest."*
- `handleExport` attaches `explanation` to the exported JSON bundle if generated.

### App Two: Consumer (`apps/consumer`)
- Genuinely independent offline application (zero network requests, zero analysis packages).
- When a bundle is imported:
  - Executes 4 sequential checks: Schema &rarr; Subject Address &rarr; Evidence Reference Integrity &rarr; Cryptographic SHA-256 Integrity.
  - If `bundle.explanation` is present, renders a distinct **Imported Qualitative Explanation (Display Only)** card.
  - Prominently displays:
    > **Non-Payload Display Metadata**: This qualitative explanation was attached to the envelope by the generator. It is NOT part of the canonical payload and is NOT verified by the cryptographic SHA-256 integrity check.
  - Displays cited evidence references and confirms all are present in the imported bundle's evidence list.
